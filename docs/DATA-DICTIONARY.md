# 保费补退定义

每份保单有且仅有一条issue基线。change按effective、责任、version选版；同生效日同版本矛盾拒绝。cancel必须引用同保单的change，取消整份变更，不按录入顺序覆盖。区间为[start,end)。年度保费按所在自然年365或366日拆分，跨年强制切段。先求每段精确保费，再最大余额法分配到分，使段合计等于保单总额。paid为已收金额，总应收减已收为补退额，正数补缴、负数退费。

## 通用采信约定

CSV按UTF-8 BOM、UTF-8、GB18030回退，保留逻辑记录结束行号；引号内换行由CSV解析。重复表头单独计数，列数不齐隔离。编码与ID按字符串保形。缺失哨兵为 `-`、`N/A`、`NULL`、`未知` 与空串；不得作为零。数值先NFKC归一、去千分位，再用Decimal。日期采用ISO；时间必须带偏移并转UTC。空文件、全空行、仅表头分别返回EMPTY_FILE、BLANK_FILE、HEADER_ONLY。

重复键为(id,version)，完全相同行去重；同键内容冲突则整组隔离，不取最后一行。行数对账：输入=采纳+隔离+空行+重复表头+完全重复。运行幂等键由输入字节、参数与规则版本计算。

## 退票与退费指令（裁决口径）

退费指令由重算产生：difference为负即生成退费指令，退费号 `RF-` 前缀，由保单、退费额与规则版本派生，与退票参数无关，退票前后保持稳定。退费指令一经发出不撤销、不覆盖，状态为已发出或已送达。

银行退回的原期缴扣款经 `parameters.bounces` 登记：`{event_id, policy_id, amount, refund_delivered}`。event_id为银行退票事件号，是幂等键；同一事件重复提交只记一笔，不新增指令、不重复收回。amount必须为正且同一保单累计退票不得超过该保单已扣金额；refund_delivered仅接受JSON布尔，表示退票到达时退费是否已送达。每笔退票生成收回指令 `RC-事件号`，关联该保单退费号。

后续安排唯一：退费未送达时退票到达，退费与收回互抵，按净额执行；退费已送达后退票到达，收回全额挂账并入下次扣款。复核页与结案下载共用三口径：已退=退费指令合计，被退回=退票事件合计，待收回=收回未核销余额；恒等式 被退回=抵销+待收回 始终成立。执行状态逐保单推导：收回挂账、退费已送达·待收回、抵销后待收回、抵销结案、抵销后净退。

指令凭据只增不改：更正只能追加新指令，旧指令留账；复核签审版本冲突返回409并保留旧版；批次存储先到为准，覆盖写入被丢弃。
